# Workstream Health Report

Generated by the VeloCity Workstream Reliability Framework (WRF) — Phase 7.

## How Health Is Computed

Health is computed by `aggregatePlatformHealth(tenantId)` in `src/lib/workstream/health-aggregator.ts`.

The aggregator runs five independent checks and combines them into a `PlatformHealthReport`:

### 1. Database Health
Executes a lightweight `SELECT COUNT(*)` against the `tenants` table using the admin Supabase client. If the query fails, Supabase is marked `offline`.

### 2. Redis Health
Calls `checkRedisHealth()` from `@/lib/redis`. Returns `{ configured, reachable, latencyMs }`. If not configured: `unknown`. If configured but unreachable: `offline`. Otherwise `healthy`.

### 3. AI Health
Checks `env.ANTHROPIC_API_KEY`. If absent or contains `placeholder`, marked `unknown`. Otherwise `healthy`.

### 4. Payment Health
Checks `env.STRIPE_SECRET_KEY`. If absent or contains `placeholder`, marked `unknown`. Otherwise `healthy`.

### 5. Queue / Worker Health
Queries `automation_queue` for stuck items (age > 10 minutes, not completed/failed). Queries `automation_runs` for recent failures (last 30 minutes). Returns queue depth, stuck item count, and worker failure count.

## Overall Health Calculation

```
worstHealth(criticalDependencies) => overall
```

- All critical dependencies healthy → `healthy`
- Any critical dependency degraded → `degraded`
- Any critical dependency offline → `offline`

## Health Report Structure

```typescript
interface PlatformHealthReport {
  workstreams: WorkstreamHealthEntry[];   // 14 entries
  dependencies: Record<string, DependencyHealthEntry>;
  workers: WorkerHealthEntry;
  queues: QueueHealthEntry;
  runtime: RuntimeHealthEntry;
  health: WorkstreamHealth;              // overall
  errors: string[];
  generatedAt: string;                   // ISO 8601
}
```

## Accessing the Report

**Dashboard:** `/admin/runtime/workstreams`
Requires `admin` or `super_admin` role. Server-rendered; auto-refreshes on page reload.

**API:** `GET /api/admin/runtime/workstreams`
Returns JSON with full `PlatformHealthReport`. Used by monitoring agents and the deployment gate.

## Alerting Thresholds

| Metric | Warning | Critical |
|--------|---------|----------|
| Worker failure rate | > 5% in 30 min | > 20% in 30 min |
| Queue depth | > 100 items | > 500 items |
| Stuck items (>10 min) | > 10 | > 50 |
| Dependency latency | > SLA × 0.8 | > SLA |

## Historical Health

The `lastSuccess` field on each workstream records the ISO timestamp of the most recent successful execution. This is persisted via session continuity for browser-side workstreams, and via the `automation_runs` table for server-side workstreams.
