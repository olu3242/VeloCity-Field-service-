# Workstream Dependency Graph

Generated by the VeloCity Workstream Reliability Framework (WRF) — Phase 5.

## Platform Dependencies

Each platform dependency is monitored continuously by the health aggregator.

| Dependency | Type | Critical | Workstreams That Depend On It |

## Dependency Impact Analysis

### If Supabase goes offline
All 14 workstreams transition to `offline`. No read or write operations are possible. Manual failover is required.

### If Redis goes offline
7 workstreams enter `degraded` mode:
- `dispatch` — loses real-time slot caching; falls back to DB reads
- `job-lifecycle` — loses status pub/sub; polls DB
- `provider-matching` — loses geo cache; recalculates from DB
- `customer-experience` — loses session cache
- `ai-orchestration` — loses prompt cache; costs increase
- `automation-engine` — queue not available; falls back to pg_cron
- `digital-twin` — loses streaming state

### If Stripe goes offline
3 commercial workstreams enter `degraded`:
- `payments` — no new payment processing; existing bookings unaffected
- `membership` — subscription validation falls back to DB cache
- `commercial` — quote/invoice generation continues; payment capture blocked

### If Anthropic goes offline
2 intelligence workstreams enter `degraded`:
- `ai-orchestration` — AI dispatch recommendations unavailable; rule-based fallback activates
- `executive-intelligence` — report generation delayed; cached reports served

## Dependency Declaration Format

Dependencies are declared in `src/lib/workstream/registry.ts` per workstream:

```typescript
{
  id: "dispatch",
  dependencies: ["supabase", "redis", "google-maps"],
  // ...
}
```

At runtime, the executor verifies each declared dependency via `aggregatePlatformHealth()` before executing. Unhealthy dependencies trigger the recovery ladder unless the workstream is configured to tolerate degraded dependencies.

## Circular Dependency Policy

No circular dependencies are permitted between workstreams. Each workstream is isolated — they share platform dependencies (supabase, redis, stripe) but never call each other directly. Cross-workstream communication occurs exclusively through database events and the automation engine.
