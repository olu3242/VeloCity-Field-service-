# Workflow Trace Report

Generated by the VeloCity Workstream Reliability Framework (WRF) — Phase 13.

## Overview

Every workstream execution is assigned a W3C traceparent-compatible correlation ID. This document describes how traces flow through the system end-to-end.

## Trace Identifiers

| Identifier | Scope | Source |
|------------|-------|--------|
| `correlationId` | Logical operation (stable across retries) | `generateRequestId()` from `@/lib/tracing/span` |
| `requestId` | Individual attempt | `generateRequestId()` |
| `workflowId` | Multi-step workflow (booking, dispatch, etc.) | Set by caller context |

## Span Lifecycle

A span is created for each stage execution via `withSpan()`:

```
SPAN START
  workstream: "dispatch"
  stage: "execute"
  correlationId: "c7f2a1b3..."
  requestId: "r9e4d2c1..."
  startedAt: "2024-01-15T10:30:00.000Z"
    ↓
  [stage execution]
    ↓
SPAN END
  latencyMs: 142
  status: "success" | "error"
  error?: WorkstreamError
```

## End-to-End Trace: Dispatch Workstream

Example trace for a dispatch request:

```

2. resolve-tenant     [5ms]  → tenant_id extracted from JWT
3. resolve-franchise  [8ms]  → franchise record loaded from DB
4. validate-membership[3ms]  → subscription tier checked
5. validate-rbac      [2ms]  → "admin" role confirmed
6. load-dependencies  [45ms] → supabase ✓, redis ✓, google-maps ✓
7. execute           [142ms] → job assigned to provider
8. persist            [28ms] → assignment written to DB
9. publish-events      [5ms] → booking_confirmed event enqueued
10. notify             [3ms] → SMS dispatched via Twilio
11. observe            [1ms] → telemetry recorded
12. recover            [0ms] → (skipped; no failure)
13. certify            [1ms] → SLA: 245ms / 3000ms ✓
```

Total: 245ms (SLA: 3000ms) — HEALTHY

## Trace Propagation

Traces propagate through:

1. **Browser → API**: `correlationId` included in request headers (`X-Correlation-Id`)
2. **API → Supabase**: embedded in function context
3. **API → Queue**: stored in `automation_queue.payload.correlationId`
4. **Queue → Worker**: extracted from payload
5. **Error display → Admin dashboard**: `?correlation=<id>` query param

## Querying Traces

To find all events for a specific correlation:

```sql
SELECT *
FROM automation_runs
WHERE payload->>'correlationId' = 'c7f2a1b3...'
ORDER BY created_at;
```

To find all workstream failures for a tenant in the last hour:

```sql
SELECT *
FROM automation_runs
WHERE tenant_id = 'tenant-uuid'
  AND status = 'failed'
  AND created_at > NOW() - INTERVAL '1 hour'
ORDER BY created_at DESC;
```

## Trace Sampling

All traces are captured in development. In production, full traces are captured for:
- All failed executions
- Executions exceeding SLA × 0.8
- All admin-triggered diagnostics

Sampling rate for successful, within-SLA executions: 10% (configurable via `WORKSTREAM_TRACE_SAMPLE_RATE` env).

## Accessing Traces

The admin dashboard at `/admin/runtime/workstreams?correlation=<id>` provides trace-level detail for a specific execution when a correlationId is supplied via query parameter.
