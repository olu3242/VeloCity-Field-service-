# Agent Trigger Certification (Remediation & Go-Live Hardening Batch, Phase 3)

Per-method audit of the 6 Batch X+3 agent extension methods flagged across `RISK_REGISTER.md` #4, `KNOWN_LIMITATIONS.md`, and `AGENT_WORKFORCE_CERTIFICATION.md`. The prior disclosure described them as "page-render-only" (executed when an admin views Command Center). Re-tracing every call site found that was **inaccurate**: Command Center calls the underlying `compute*()` lib functions directly for 3 of the 6 methods, and doesn't call the lib functions for the other 3 at all — meaning all 6 agent-class wrapper methods had **zero callers anywhere in the codebase**, not merely "no autonomous trigger."

| Method | Purpose | Expected Trigger (per design intent) | Current State (before this batch) | Decision |
|---|---|---|---|---|
| `NovaAgent.assessMarketDemand(territoryId)` | Per-category job demand for a franchise territory; persists a `market_demand` snapshot | Daily cron, alongside other territory intelligence | Zero callers. Not called by Command Center (which has no expansion-intelligence UI calling it), not called by any handler | **A — wired to a real trigger** |
| `NovaAgent.assessMarketSupply(territoryId)` | Per-category active provider supply for a territory; persists `market_supply` | Daily cron, alongside demand | Zero callers | **A — wired to a real trigger** |
| `NovaAgent.recommendExpansionOpportunities(territoryId)` | Combines demand/supply into `market_metrics`/`market_opportunities` with revenue impact | Daily cron, after demand/supply | Zero callers | **A — wired to a real trigger** |
| `MaxAgent.assessCommercialDispatchPriority(jobId, candidateProviderIds)` | Narrows a commercial job's candidate pool to Gold/Elite-certified, under-capacity providers; computes SLA deadline | Inline in commercial-job dispatch, before `MAX.match()` | Zero callers — `handleMaxDispatch` ran `MAX.match()` against the full candidate pool for every job, commercial or not | **A — wired to a real trigger** |
| `FinnAgent.calculateCommercialRevenue()` | Commercial revenue/contract attainment/renewal pipeline | Command Center revenue section | Zero callers — Command Center imports and calls `computeCommercialRevenueIntelligence()` from `commercialRevenueIntelligence.ts` directly, never through this wrapper | **B — deprecated and removed** |
| `GabrielAgent.generateExecutiveBriefing()` | Aggregates FINN/ALICE/NOVA reports into one executive briefing | Command Center executive section | Zero callers — Command Center imports and calls `computeExecutiveIntelligence()` from `executiveIntelligence.ts` directly | **B — deprecated and removed** |

## Decision A: wired to a real trigger

**NOVA's 3 methods** are now called from `handleTessTerritory` (`src/lib/automation/handlers/tess-territory.ts`), the existing handler for the `daily_territory_analysis` event — itself emitted by the `/api/cron/daily-intelligence` Vercel cron (`vercel.json`, `0 6 * * *`). No new cron, event type, or handler was added; the existing daily territory-analysis handler was extended to also loop over every `status = 'active'` row in `franchise_territories` and call `assessMarketDemand` → `assessMarketSupply` → `recommendExpansionOpportunities` for each, with a per-territory summary folded into the same `audit_logs` row TESS already writes for this event. This is now a real, cron-driven, autonomous execution path — not page-render-only.

**MAX's method** is now called from `handleMaxDispatch` (`src/lib/automation/handlers/max-dispatch.ts`), the handler for `serviceability_passed` (the event that triggers provider dispatch). It runs unconditionally before `MAX.match()`; for a non-commercial job it is a no-op (`computeCommercialDispatchPriority` returns the full candidate pool unchanged when `jobs.commercial_contract_id` is null — this fallback already existed in the lib function and required no change). For a commercial job, the candidate pool is narrowed to `eligibleProviderIds` before `MAX.match()` ranks it; if narrowing eliminates every candidate, the job follows the same `no_provider_accepted` escalation path already used for the non-commercial empty-pool case. This is now wired into the real dispatch event path for every job dispatch, not just commercial-account page renders.

## Decision B: deprecated and removed

`FinnAgent.calculateCommercialRevenue()` and `GabrielAgent.generateExecutiveBriefing()` were removed from `src/lib/agents/finn.ts` and `src/lib/agents/gabriel.ts`. Both were thin pass-throughs (`return computeXIntelligence()`) that bypassed `BaseAgent.run()`/`.log()` entirely (no LLM call, no `agent_logs` evidence), and both had zero callers — Command Center already gets the same data by calling `computeCommercialRevenueIntelligence()` and `computeExecutiveIntelligence()` directly. Keeping the wrapper methods added no evidence value over the direct calls and constituted dormant code with no execution path, which the batch's mandate ("no dormant production code") requires resolving. Removing them is more honest than fabricating a trigger for a reporting rollup that has no autonomous action to take — these are read-time aggregations of already-certified reports, not actions that need to "fire." The underlying `compute*Intelligence()` functions are untouched and remain Command Center's single source for this data, exactly as before.

`FinnAgent.calculateRecurringRevenue()` (an earlier, Batch X+2 method with the same dead-wrapper pattern, confirmed via the same call-site audit) was **not** in scope for this batch's named finding list and was left untouched to avoid scope creep beyond the 6 named methods — it is recorded here for visibility and should be folded into the next remediation pass if it remains uncalled.

## Verification

- `npx tsc --noEmit`, `npm run lint`, `npm run build` all pass after the wiring and removal changes (see root commit for this batch).
- Grepped the full `src/` tree post-change: `assessMarketDemand`, `assessMarketSupply`, `recommendExpansionOpportunities`, and `assessCommercialDispatchPriority` each now have exactly one caller (their respective handler); `calculateCommercialRevenue` and `generateExecutiveBriefing` have zero remaining references anywhere, including in their own former files.

**Status: CERTIFIED ✅** — no orphaned agent method remains. Every method on every agent class is either called by a real trigger (event/cron/API route) or has been removed.
