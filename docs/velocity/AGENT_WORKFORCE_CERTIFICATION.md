# Agent Workforce Certification (Platform Certification Batch, Phase 3)

All 10 agents extend `BaseAgent` (`src/lib/agents/base.ts`), which provides `run()` (calls Claude, parses JSON, always logs) and a private `log()` that inserts into `agent_logs` on every invocation, success or failure (`base.ts:83-101`). Every agent is registered in `AGENT_REGISTRY` (`src/lib/agents/registry.ts`), which `buildAgentActivitySummary()` (`src/app/admin/command-center/page.tsx:49-69`) uses to compute per-agent execution count, success rate, average runtime, and last-execution time for the Command Center's "AI Agent Activity" table — this is the platform's single agent-visibility mechanism; no agent has a bespoke dashboard.

## Findings

1. **9 of 10 agents have a genuine trigger → execution → evidence → visibility chain** reachable from either a real user action (API route) or a real automation event (`router.ts` dispatch) or cron.
2. **GABRIEL's core function (governance audit) fires unconditionally on every event** — this is the strongest-evidenced agent in the platform; its newer `generateExecutiveBriefing()` method (Batch X+3) is read-time only and has no event trigger, which is appropriate since it's a reporting rollup, not an action.
3. **Disclosed gap**: Batch X+3's expansion/commercial extension methods — `NovaAgent.assessMarketDemand/assessMarketSupply/recommendExpansionOpportunities`, `FinnAgent.calculateCommercialRevenue`, `MaxAgent.assessCommercialDispatchPriority`, `GabrielAgent.generateExecutiveBriefing` — are **PARTIAL** on the Trigger axis: they execute and log correctly when called, and are visible in Command Center, but none of them currently have an automation-event or cron trigger. They are invoked only by the Command Center's own page-render code path. This is consistent with Phase 1's capability inventory and does not block certification (no business flow depends on them firing autonomously yet), but is recorded here and in `KNOWN_LIMITATIONS.md`.
4. **REX's `provider_scoring` event path bypasses the LLM and `agent_logs`** by design (deterministic trust-score math) — this is intentional (avoids LLM cost/latency for a formula-driven update) but means Command Center's REX execution count under-reports actual trust-score update frequency. Recorded in `KNOWN_LIMITATIONS.md`.

**Status: CERTIFIED ✅**, with the two disclosed PARTIAL items above carried into the Risk Register and Known Limitations docs rather than blocking the gate — none of the 10 agents is unreachable, undocumented, or silently failing.
