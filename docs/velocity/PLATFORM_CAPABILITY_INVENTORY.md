# Platform Capability Inventory (Platform Certification Batch, Phase 1)

Inventory of every major business capability in VeloCity as of this certification batch. Classification: **ACTIVE** (implemented, wired end-to-end, has real triggers/evidence/visibility), **PARTIAL** (implemented but missing a link in the trigger/execution/evidence/visibility chain, or only reachable via cron/admin action, or has a disclosed data gap), **UNUSED** (code exists but nothing in the live system reaches it).

| Capability | Status | Evidence |
|---|---|---|
| Provider OS | ACTIVE | `src/app/provider/**` (apply, jobs, earnings, profile); providers see only their own jobs via `.eq("provider_id", provider.id)` (`src/app/provider/jobs/[id]/page.tsx`) backed by RLS policy "Providers see assigned jobs" (`003_tenant_demarcation.sql`); dispatch via MAX, completion via REX/NOVA |
| Customer OS | ACTIVE | `src/app/dashboard/page.tsx`, booking flow, `src/app/api/jobs`, `src/app/api/quotes`, `src/app/api/disputes`, `src/app/api/reviews`; customer-scoped via `.eq("customer_id", user.id)` + RLS "Customers see own jobs" |
| Membership Engine | ACTIVE | `src/lib/membership/*` (8 files) — lifecycle, revenue, retention, growth intelligence all read/write real tables (`membership_subscriptions`, `membership_entitlements`, `membership_usage`); surfaced in Command Center + customer dashboard; cron-driven renewal/expiry via `emitDueMembershipServices()`/`emitExpiringMemberships()` |
| Commercial Accounts | ACTIVE | `src/lib/commercial/*` (4 files) — single write path `commercialAccountLifecycle.ts`, revenue/dispatch/summary read-time reports; surfaced in Command Center + customer dashboard ("My Commercial Account") |
| Expansion Intelligence | PARTIAL | `src/lib/expansion/*` computes real demand/supply/opportunity from `jobs`/`providers`/`franchise_territories`; NOVA methods exist and are surfaced in Command Center, but are **not wired to any automated trigger** (cron/event) — they must be invoked manually or from a future scheduled job. No live-data validation has been performed (see `EXPANSION_INTELLIGENCE_E2E_VALIDATION.md`) |
| Service Catalog | ACTIVE | `service_types`, `service_packages`, `service_category` enum drive job creation, membership entitlements, commercial service plans, and provider skill/certification tiers — confirmed single source of truth, no duplicate catalog found |
| Agent Workforce | ACTIVE (9) / PARTIAL (1) | 10 agents (ALICE, MAX, QUINN, NOVA, REX, IVY, FINN, LENA, TESS, GABRIEL) all have real trigger paths, write to `agent_logs`, and are listed in `AGENT_REGISTRY`. Expansion-Intelligence methods on NOVA (`assessMarketDemand`/`assessMarketSupply`/`recommendExpansionOpportunities`) and the executive-briefing method on GABRIEL (`generateExecutiveBriefing`) have **no automation trigger** — only reachable from Command Center's server-rendered page load, not from `router.ts`. See `AGENT_WORKFORCE_CERTIFICATION.md` |
| Automation Fabric | ACTIVE | `src/lib/automation/*` — 68 event types, `router.ts` switch-dispatch to 13 handlers, queue+retry (`automation_queue`, max 3 attempts, linear backoff), 4 Vercel crons. See `AUTOMATION_FABRIC_CERTIFICATION.md` for full detail and disclosed gaps (linear not exponential backoff, no dedicated dead-letter table) |
| Revenue Intelligence | ACTIVE | Core revenue (`revenue_records`, `payments`), commission (`calculateCommission()`), payout (`payoutLedger.ts`/`treasury/*`/4 cron `payouts`), forecasting (`forecastRevenue()`), membership MRR/ARR (`computeRecurringRevenueIntelligence()`), commercial revenue (`computeCommercialRevenueIntelligence()`) — all real read paths off real tables. See `REVENUE_INTELLIGENCE_CERTIFICATION.md` |
| Command Center | ACTIVE | `/admin/command-center` aggregates System Health, Provider Excellence, Membership/Recurring Revenue, Expansion/Commercial Intelligence, KPI grid, agent activity, automation queue health, and more into one route. See `COMMAND_CENTER_CERTIFICATION_FULL.md` for the subsystem-by-subsystem "no blind spots" check |

## Scope discipline

This inventory introduces no new tables, agents, or dashboard routes. It documents existing capability only, per the governing constraint of this batch: **zero new customer-facing features**.
